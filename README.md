# 키오스크 접근성 OpenCV·OCR 프로토타입

시각장애인 사용자가 기존 키오스크의 프로그램을 변경하지 않고도 메뉴 위치를 찾을 수 있도록 설계한 탐구용 시제품입니다. 스마트폰 앱의 완성품이 아니라, 보고서에 제안된 영상처리·OCR·촉각 격자 알고리즘을 PC와 웹캠에서 검증하는 단계입니다.

## 구현된 기능

- 가장 큰 사각형 화면 검출 및 카메라 정렬 방향 계산
- 네 모서리를 이용한 원근 보정과 600×1000 좌표 정규화
- Tesseract 기반 한글·영문 OCR 및 문자 경계 상자 추출
- 확대 컬러 PSM 11과 텍스트 블록 PSM 6을 결합한 다중 경로 OCR
- 흐림·저대비 화면의 CLAHE 보조 인식과 OCR 처리 시간 제한
- 최근 약 2초의 프레임 중 선명도·노출 품질이 가장 좋은 장면 자동 선택
- 약한 손떨림은 원근 보정 후 허용하고 강한 흔들림·모션 블러는 자동 제외
- 화면 테두리를 잠시 놓쳐도 최대 4프레임 광학 흐름 추적으로 연결
- 동일 위치 다중 인식 결과 병합과 한 글자 잡음 제거
- 항목별 OCR 신뢰도와 흐림·반사·저조도 촬영 안내
- OCR 중심 좌표를 A~F, 1~10 촉각 격자로 변환
- 같은 격자 안의 여러 항목에 왼쪽·오른쪽 또는 위·아래 정보 추가
- 중간 정도의 손떨림에서도 선명 후보가 모이면 자동 분석
- Windows 카메라 장치명을 읽어 Camo/iPhone을 우선 선택하고 프레임 워밍업
- Camo의 기본 RGB 포맷을 유지하고 완전 검은 초기 프레임은 화면에 표시하지 않음
- `연결 중·프레임 수신 중·연결 불안정·연결 해제` 상태를 별도 표시
- 카메라 번호 직접 선택과 일시적인 프레임 실패 자동 재시도
- 화면 변화량이 기준값을 넘으면 재분석
- OCR 백그라운드 처리로 분석 중에도 웹캠과 창이 계속 응답
- 자동 재분석 이후에도 사용자가 선택한 메뉴 유지
- 사용자가 입력한 메뉴명과 OCR 결과의 공백·일부 오차를 비교해 목표 자동 선택
- 현재 카메라 중심점을 원근 보정된 600×1000 화면 좌표로 실시간 변환
- 카메라 중심점에서 목표 문자까지의 방향·정규화 거리·접근 속도 계산
- 원본 화면의 목표 역투영 상자와 보정 화면의 실시간 십자선 표시
- 거리에 따른 진동 간격을 색상 펄스로 보여 주고 목표 일치 시 연속 진동 표시
- 화면 테두리가 보이지 않는 경우를 위한 전체 프레임 OCR·추적 보조 모드
- 음성인식 없이 목록·방향키·Enter로 메뉴 선택
- 자연스러운 한국어 신경망 음성 우선, 연결 실패 시 Windows 로컬 음성으로 자동 전환
- `R` 또는 `안내 듣기` 버튼을 누를 때만 `불고기버거, 화면 왼쪽 위에 있습니다` 형식으로 출력
- 보정 화면 클릭 시 클릭 지점을 현재 위치로 사용해 상대 방향을 다시 계산하고 `R`로 확인
- 선택 목표까지 거리에 따른 진동 간격 시뮬레이션
- 실제 OCR 없이도 실행 가능한 내장 모의 키오스크

## 바로 실행

PowerShell에서 프로젝트 폴더로 이동한 뒤 실행합니다.

```powershell
.\run.cmd
```

처음 열리면 내장 모의 키오스크가 자동 분석됩니다.

1. `내장 데모`, `사진 열기`, `웹캠 시작` 중 하나를 선택합니다.
2. 웹캠에서는 키오스크 화면의 네 모서리가 모두 보이도록 비춥니다. 완전히
   고정하지 않아도 되며, 프로그램이 흔들리는 장면 중 선명한 순간을 고릅니다.
3. `찾을 메뉴 입력`에 `불고기버거`처럼 메뉴명을 쓰고 `찾기·추적`을 누릅니다.
4. OCR 결과에서 목표가 선택되면 카메라 중심 십자선과 노란 목표 상자를 확인합니다.
5. 화면에 표시되는 방향과 거리 안내에 따라 움직이면 진동 간격이 감소합니다.
6. 테두리를 찾지 못하지만 화면이 카메라를 거의 채운다면 `전체 프레임 OCR`을 누릅니다.

내장 데모나 사진에서는 목표 메뉴를 선택한 뒤 화면의 임의 지점을 클릭해 보세요.
클릭한 곳을 현재 손가락 위치로 보고 `불고기버거, 오른쪽 아래에 있습니다`처럼
목표의 상대 방향을 다시 계산합니다. `R` 또는 `안내 듣기` 버튼을 누르면
계산된 위치 안내만 말하며, 격자와 OCR 신뢰도는 음성으로 읽지 않습니다.

글자가 잘못 인식되면 화면의 네 모서리를 유지한 채 천천히 움직여 선명 후보를
다시 모으거나 `화면 인식·다시 OCR (F5)`을 누르세요. 강하게 흔들려 글자가
번진 프레임은 분석하지 않고 상태창에 `선명한 순간을 기다리는 중`이라고
표시합니다. 목록의 `높음/확인 필요/낮음`과 신뢰도 수치를 확인하고, 유사한
후보는 목록에서 직접 클릭해야 목표 추적이 시작됩니다.

사진과 내장 데모에서는 목록을 클릭하거나 방향키·Enter로 목표를 선택한 뒤,
보정 화면 위에서 마우스를 움직여 같은 진동 계산을 시험할 수 있습니다.

키보드만으로도 주요 기능을 실행할 수 있습니다.

- `F2`: 웹캠 시작 또는 중지
- `F3`: 사진 열기
- `F4`: 내장 데모
- `F5`: 현재 화면 분석
- `R`: 현재 선택 메뉴의 위치 안내 듣기
- `Esc`: 웹캠 중지

아이폰에서 Camo를 사용한다면 Camo Studio의 영상 미리보기를 먼저 확인한 뒤
`자동 탐색 (Camo/iPhone 우선)`을 선택하세요. 프로그램이 Windows 장치명에서
Camo를 찾으면 저채도 장면에서도 내장 카메라보다 먼저 연결하고, 선택 목록과
연결 상태에 `Camo/iPhone`을 표시합니다. 자동 연결이 되지 않으면 목록에서
`Camo/iPhone (카메라 번호)`를 직접 선택할 수 있습니다. Camo Studio는
실행해 두되 Discord처럼 Camo 가상 카메라를 사용하는 다른 앱은 닫아야 합니다.

한국어 음성은 `ko-KR-SunHiNeural`을 우선 사용하므로 첫 재생에는 인터넷
연결이 필요할 수 있습니다. 같은 안내는 임시 캐시에 저장되어 다시 들을 때
빠르게 재생됩니다. 연결이나 오디오 재생에 실패하면 설치된 Windows 한국어
음성으로 자동 전환됩니다.

GUI 없이 결과 이미지만 만들려면 다음을 실행합니다.

```powershell
.\run.cmd --demo
```

OCR 엔진과 무관하게 좌표 변환만 검증하려면 다음을 실행합니다.

```powershell
.\run.cmd --static-demo
```

결과는 `demo_output` 폴더에 입력 화면, 화면 검출 결과, 격자 분석 결과와 JSON으로 저장됩니다.

## 다른 PC에서 준비하기

Python 3.11~3.13 환경에서 다음 패키지를 설치합니다.

```powershell
python -m pip install -r requirements.txt
```

실제 OCR에는 별도의 Tesseract 실행 파일이 필요합니다. Windows용 설치 방법은 Tesseract 공식 문서가 안내하는 UB Mannheim 빌드를 사용할 수 있습니다. 한국어 모델 `kor.traineddata`는 `tesseract-ocr/tessdata_fast` 공식 저장소에서 받아 `.runtime/tessdata`에 둡니다.

## 촉각 격자

`assets/grid_6x10.svg`는 6열×10행 투명 격자 도안입니다. 실제 제작 시 화면 크기에 맞게 비율을 유지해 출력하고, 선 부분에 투명 돌기 스티커나 투명 실리콘을 적용할 수 있습니다. 모서리 기준점이 키오스크 화면 모서리와 정확히 맞아야 합니다.

## 현재 한계

- OCR 경계 상자는 글자 위치이며 실제 버튼 전체 영역과 다를 수 있습니다.
- 반사광, 작은 글씨, 이미지 중심 메뉴에서는 인식률이 낮아질 수 있습니다.
- 노트북 시제품에서는 카메라 중심점을 스마트폰 카메라 중심의 대리 좌표로 사용합니다.
- 데스크톱 시제품이므로 실제 스마트폰 진동 대신 화면의 색상 펄스로 진동 주기를 시뮬레이션합니다.
- 투명 격자 필름의 물리적 정렬은 실제 화면에서 별도로 검증해야 합니다.
- 실제 시각장애인 사용성 평가는 당사자와 함께 안전하고 윤리적인 절차로 진행해야 합니다.
